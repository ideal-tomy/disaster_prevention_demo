# 描写と作り込みの改善提案

作成日：2026-09-09  
対象：

- 市版 `disaster_prevention_demo`（http://localhost:3000）
- 体育館版 `disaster_prevention_demo02`（http://localhost:3011）

評価：Chrome 相当・1280×900。LP、ダッシュボード、一覧、インシデント、画像確認、書類、連携を実画面で確認した。  
操作の抜け（検索、判定の訂正、状態の横断保存）は市版 [05_UIUX改善提案書.md](05_UIUX改善提案書.md) に既にある。本書は **「AIが並べた画面」に見える理由と、描写の作り込み** に限定する。

数値・判定・Won't（暗色オペ室、Salesforce Blue、監視、被災）は動かさない。

---

## 1. 結論

今の完成度は「正しく動くモック」である。投影で残るのは検出枠だけで、他は同じ白いカードが等間隔に並んでいる。ユーザーが「作り込んだ製品」と感じる条件は、機能追加より次の3つである。

1. **2つのデモが同じテンプレに見えないこと。** LPもシェルも4枚の数字カードも同一構図である。市は22施設の地図、体育館は1棟の平面、と空間の主役を分ける。
2. **証拠写真が「コンポーネント」ではなく現場のフレームに見えること。** 検出枠は既に効いている。時刻・カメラID・紙の帳票・模式図が、同じ密度まで届いていない。
3. **一覧が「済の表」ではなく、期限と場所の景色に見えること。** 市版は「済」の反復、体育館版は3列の空白が多い。行のグループと期限の強弱が無い。

先に直す画面は、市版が **模式地図とインシデント右ペイン**、体育館版が **棟の模式とLPの差別化**。どちらも1280pxの投影で最初に見られる。

## 2. 実画面で共通して出ていた「AIらしい」印

色やフォントの問題ではない。構図が同じである。

| 印 | 実画面 | 作り込まれた画面に見える条件 |
|---|---|---|
| 4枚同じ大きさの数字カード | 両ダッシュボード上段 | 主指標は1つ。他は小さく従える。単位と「いま見ている対象」を数字の横に置く |
| 白い角丸カードの連打 | バナー、地図、連携、書類左右、チャット | 浮く面はドロワーと帳票だけ。本文は罫線と余白で分ける |
| 4つの機能カード | 両LP下段。中身だけ文言差 | 番号つきの1本の帯にする。カードを4つ置かない |
| 点の地図 | 市版は無名の点。体育館はラベルが重なる | 市は地区名。体育館は部屋の矩形。ピン名は引出線 |
| 相関の箱 | 両インシデント。箱が本文・81%と重なる | SVGの線。81%は図の外のキャプション |
| ヘッダーの均等なチップ | LIVE・14:52・日付・台風・注意・AIが同じ大きさ | 時計を主、他は一段弱く。LIVEはデモ基準時刻と書く |
| 「嶺」の同じマーク | 両LP・両シェル | 残してよいが、サブコピーで市／1棟を先に見せる |

市版と体育館版を並べると、見出し以外が同一に見える。横展開の説明としては正しいが、**見た目のクローンは「量産AIデモ」に読める。** トークンは共有したまま、LPの写真配置とダッシュボード下段の地図だけ型を変える。

## 3. 市版（localhost:3000）で見たこと

### LP

写真は大きい。見出しも正しい。しかし左文＋右写真＋下に白カード4つは、製品サイトというより生成UIの定番である。写真右上の「注意／モック」ピルが、証拠写真ではなく広告バッジに見える。

提案：

- 写真下端に細いキャプションバー（翠嶺市総合体育館 · 抽出ではない外観 · DEMO）。ピルは写真の上に重ねない
- 下段4カードを廃止し、「1 切替 → 2 写真 → 3 書類」の1行にする
- 副CTAは「AIに質問する」より「平常と災害を切り替える」（コンソールの見せ場へ直接）

### ダッシュボード

4数字は読める。地図は矩形の中の点だけで、総合体育館がどれか分からない。凡例は文字だけで、点の色と対応しにくい。インシデント帯は上のカードと同じ白面で、進行中の1本が埋もれる。

提案：

- 地図に北・中央などの粗い地区ラベル。F01だけ名前を常時出す。ホバーで施設名
- インシデント帯の左に `b1` のサムネ（16:9、枠なし）。文章だけの帯にしない
- 「使える 12」の右に「施設」。収容はカードを分けず、12の下に「収容 2,385」のまま小さく（既存）でよいが、12と2,385が別物だと一目で分かる位置にする
- 数値カードはリンクに見えるホバー（手）。遷移先は 05 のU07

### 施設一覧

トグルと表は製品らしい。弱いのは中身のリズムである。「済」が消防・発電機・受水槽・外壁・扉に並び、期限切れの行だけが赤いピル、という差が小さい。先頭の総合体育館が特別な行だと、マーク8pxだけでは分からない。

提案：

- 「済」を日付または「記録」1語にそろえる。5列とも「済」は表計算に見える
- 期限切れ行は左2pxの `--stop` と、行背景をごく薄く。全面赤にはしない
- F01行に「進行中 INC-…」の小さなテキスト。他行と密度を変える
- 列ヘッダを sticky（体育館版にはある。市版の実画面では表が短くても揃える）

### インシデント

検出枠とキャプションは本格的である。右の「相関」は箱が重なり、81%の説明文がノードに食い込んでいる。タイムラインは写真の積み上げで、時刻の軸が無い。

提案：

- 左に 2px の時刻レール。14:08 / 14:21 / 14:36 をレール上の点にする
- 写真左下にカメラIDを焼き込まないオーバーレイ（実装のキャプションと二重にしないなら、写真上か下か一方）
- 相関は中央「総合」から4本の線。ノードを本文の上に重ねない。81%は図の下
- 推奨アクションを番号付きのチェックではない文のままにするなら、行の左に未着手の空枠だけ（押して完了にしない。05のU09より軽い描写）

### 画像確認

横並びの写真＋ボタンは分かる。カードがダッシュボードと同じ白面で、現場の確認台に見えない。1件目に枠が無く、2件目に枠がある差は正しいが、未入力の行が視覚的に主になっていない。

提案：

- 未入力カードだけ左に 2px `--ai`。処理済みは一段落とす（消さない）
- 写真を 4:3 のままで、周囲に 1px `--line` と内側の暗いinset。広告ヒーローにしない
- ボタンは写真の下ではなく右ペイン下部に固定し、高さを44pxのまま揃える

### 書類

2枚の帳票が同じkvリストである。紙に見えない。下の対応表は良いが、帳票との視線が切れている。

提案：

- 帳票面だけ `--paper` よりわずかに暖かい地（例: `#F7F4EE`）。カードの12px角丸は帳票だけ 2px
- 左に「下書き」の斜めスタンプは出さない（DEMO表記で足りる）。代わりに右上に「下書き」ピル1つ
- 対応表の行ホバーで左右帳票の該当欄が同じ地色（体育館版の実装を市版へ戻す）

### 連携

5/8 とバーは分かる。実画面で「100%」がバーに隠れている（親の overflow と負の top）。05 U12 系のクリップそのもの。

提案：パーセント文言はバーの上の兄弟要素へ移す。未確認行の破線ドットは残す。

## 4. 体育館版（localhost:3011）で見たこと

市版と同じシェルなので、差が付くべき場所は **模式図、トグル、18行の表、LPの1行目** である。今は差がコピーに留まっている。

### LP

見出しは体育館用になっている。写真・4カード・CTAの位置は市版と同一。横に投影すると「同じデモの色違い」に見える。

提案：

- ヒーローを縦位置で変える。市版は右に4:5。体育館は写真を全幅の低い帯（外観 e1 または a1 の横位置トリミング）＋その下に見出し、でもよい。カード4つは置かない
- 「場所と設備18」を数字として見出し近くに出す（市の「22施設」と並んだとき差が先に出る）

### ダッシュボード

4数字は正しい。模式が破綻している。実画面では「屋上」と N02、「空調」とラベル、「東側搬入口」と E01 が重なる。矩形2つでは体育館に読めない。ピン10を全部名前付きで置いた結果、地図が読めなくなっている。

提案（04の座標は正のまま、描画だけ変える）:

- 部屋を先に描く。アリーナ大きな矩形、サブアリーナ東、搬入口東の切れ込み、非常口西。ピンは部屋の中心の点だけ。名前は図の外か、ホバー時
- 初期から名前を出すのは Z01 と Z02 だけ（03どおり「同時に読める」）。他は点＋凡例
- カメラは点ではなく小さな楔（向き）。IDはホバーか選択時
- 連携カードの「5 / 8」は地図より視覚が強い。地図を主、連携は1行の進捗に落とす

### 設備・場所

保全の表は種別・業者が繰り返し、空白が多い。期限切れはピルだけ。トグルは機能するが、切替の「同じ行」が視覚的に主張していない。

提案：

- 種別でグループ行を入れる（競技場、動線、機械…）。並べ替えはしない
- 業者「指定管理」は1列で薄く。期限列を等幅で主にする
- 切替時、列名「期限 → 判定」をクロスフェード（仕様どおり）に加え、左の印だけ 150ms で色が乗る。行は動かさない
- 屋上・空調は開館時、理由列を「記録がない」のまま。ピルより破線マークを先に見せる

### インシデント

検出枠は市版と同じ強さ。右上が壊れた模式、その下が重なった相関で、証拠の左よりノイズが勝っている。

提案：

- 右上の模式はダッシュボードと同じコンポーネント。タイムライン連動時だけ該当ピンの名前を出す
- 相関の箱を模式の下に置かず、模式を外して相関だけにするか、模式を1つに減らす（今は両方とも失敗している）
- 14:36 のキャプション「3日前の入力と同じ場所」を写真の直下で太くする（知見継承の見せ場）

### 画像確認・書類

白バン押下後に発電機が上がる動きは、操作としては作り込みに近い。書類の確認者が岡田になるのも同じ。見た目は市版と同じkv帳票なので、紙に寄せる描写は市版と共通で直す。ホバーハイライトは残す。左右の対応が光るとき、帳票側も同じ行が光ると「同じ記録」が目に残る。

## 5. 描写の共通仕様（両デモ）

トークンの色は変えない。変えるのは階層と面の使い方。

| 項目 | 今 | 提案 |
|---|---|---|
| 面 | ほぼ全て `--surface` 12px | ページ地 `--paper`。表と帳票だけ面。地図は線画 |
| 影 | ほぼ無し／LPだけ | ドロワーとヘッダー以外に影を足さない |
| 数字 | 32pxが4つ | 主1つ 40px、従 22px。単位 12px `--muted` |
| ヘッダー | 要素が横に均等 | `14:52` を 18px。LIVEは「基準」に変更するか、点だけ残して文字を DEMO |
| ナビ | 現在地が白背景 | 左 2px `--ink`（体育館はCSSにあるが実画面では弱い）。アイコンは足さない |
| 写真 | 角丸10px＋平坦 | 角丸 4px。検出枠のある枚だけを「証拠」 |
| 空欄 | 「—」 | そのまま。イラストで埋めない |

動きは増やさない。足してよいのは (1) トグルの列クロスフェード (2) 検出枠の opacity (3) 帳票ハイライト。常時のパルス、地図のズーム、数字のカウントアップは禁止（AIっぽさが増える）。

## 6. 優先順位

投影2分で効く順。05のP0（訂正・保存）とは別予算でよい。

| 順 | 対象 | 内容 | なぜ先か |
|---|---|---|---|
| A | 体育館 模式 | 部屋の矩形＋名前は Z01/Z02 のみ。重なりを消す | 今いちばん「未完成の生成図」に見える |
| B | 両 インシデント右 | 相関の重なり解消。81%を図の外へ | 見せ場の隣が壊れている |
| C | 両 LP | 4カード廃止。写真キャプション。2デモで構図を変える | 入口でテンプレ判定される |
| D | 市 地図 | F01の名前、地区、インシデント帯にサムネ | 市版の空間が点群のまま |
| E | 両 一覧 | 済の反復をやめる。期限切れ行の左線。グループ行（体育館） | 毎日触る画面 |
| F | 両 書類 | 帳票の地色と罫線。対応表と欄の同期ハイライト（市へも） | 締めの画面がkvの複製 |

やらない（今のAIっぽさを増やす）:

- グラデーションのヒーロー、ガラスのカード増殖、数字のアニメ
- ダークモード、青のリブランディング
- 地図のヒート、3D、断面タワー
- 機能カードを6つに増やす

## 7. 受け入れ（描写）

ブラウザ 1280×900 で次を満たせば、操作のP0が未着手でも「テンプレ感」は下がる。

- 市版と体育館版のLPを並べたとき、写真の置き方か下段の形が違う
- 体育館の模式で、ラベルがカメラIDと重ならない。アリーナと搬入口の名前が初期から読める
- インシデント右ペインで、本文とノードが重ならない
- 施設／場所一覧で、「済済済」が5列に並ばない（市）。先頭行がアリーナ／総合体育館のまま
- 書類がダッシュボードの白カードと同一に見えない
- 連携の「100%」がバーに隠れない

## 8. 05との役割

| 文書 | 扱うこと |
|---|---|
| 市版 05 | 検索、詳細のキーボード、判定の訂正と横断保存、施設セレクタ |
| 本書 | 地図・写真・帳票・カード階層・2デモの見た目の差 |

両方必要である。05だけだと正しい業務アプリに近づくが、画面はまだ生成UIに見える。本書だけだと綺麗だが、押したあとの記録が切れたままである。実装するなら A〜D を先に、05のP0は並行でも後でもよい。
