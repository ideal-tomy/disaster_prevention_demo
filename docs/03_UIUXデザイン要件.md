# UIUXデザイン要件｜防災施設コンソール

実装者がワイヤーとトークンで組むための仕様。文言の数字、施設名、時刻は [04_ペルソナと仮ナレッジ.md](04_ペルソナと仮ナレッジ.md) と一致させる。写真は [02_画像仕様と生成プロンプト.md](02_画像仕様と生成プロンプト.md)。画面の目的は [01_テーマ別要件定義書.md](01_テーマ別要件定義書.md)。

仮称は「防災施設コンソール」。英語の OS 名は出さない。

---

## 1. コンセプト

危機管理センターの暗いオペ室にしない。総務課で施設管理を兼務する人が、会議で投影して説明できる、静かな運用コンソール。

シグネチャーは2つだけ。ここに演出を寄せる。

1. 施設一覧の「平常 / 災害」トグル。並びと名前は変わらず、期限が開設判定に変わる
2. インシデントの抽出静止画と、その上に乗る検出枠

LPだけ、写真を大きくして価値を短く言う。コンソールの中では説明コピーを足さない。状態、写真、記録、根拠で話す。

参照してよい密度: Building OS Console のサイドバー、カード、ライブの帯。借りないもの: 断面タワー、在館、駐車場、不審行動、防犯の赤の連続。

LPの写真の置き方だけ、Appleの製品ページに寄せる。1画面で1こと。本文は短く、詳細はコンソールへ。

## 2. トークン

ライト基調。ダークテーマは初回やらない。

### 2.1 色

| トークン | 値 | 用途 |
|---|---|---|
| `--ink` | `#1C2430` | 見出し、主要数値 |
| `--paper` | `#F4F6F8` | ページ背景 |
| `--surface` | `#FFFFFF` | カード |
| `--line` | `#E4E8EE` | 罫線 1px。多用しない |
| `--muted` | `#5E6A78` | 補助、キャプション |
| `--nav` | `#F7F8FA` | 左ナビ背景 |
| `--ok` | `#1F7A4D` | 使える、記録済み、接続済み |
| `--warn` | `#C47B12` | 条件付き、今月、確認中、全体「注意」 |
| `--stop` | `#B42318` | 使えない、期限切れ。画面に同時2箇所以内 |
| `--unknown` | `#8B93A0` | 確認できていない、記録なし。破線とセット |
| `--ai` | `#5B4DB7` | AIの印、相関の中心、質問ボタン。他に使わない |

ステータス色は意味があるときだけ。装飾のグラデーションに使わない。`--stop` をヘッダー帯の全面に塗らない。全体ステータスは「注意」で `--warn`。

色だけで判定を伝えない。必ず文字を付ける（使える / 条件付き / 使えない / 確認できていない）。

### 2.2 文字

- UI: Noto Sans JP 400 / 500。600 は数値とボタンだけ
- 数値は等幅（`font-variant-numeric: tabular-nums`）
- スケール: 12 注釈 / 13 補助 / 14 本文 / 16 カード見出し / 22 画面タイトル / 28〜36 ヒーローの主要数字
- 行長: 説明が必要な箇所は全角40字まで。コンソール内の説明段落は原則置かない

### 2.3 形状と間隔

- 角丸: カード 12px、コントロール 8px、ピル 99px
- 余白: 4px グリッド。カード内 16–20px。セクション間 24px
- 左ナビ幅 232px。本文最大 1120px を中央に寄せすぎない。コンソールはナビの右を使う
- 最小幅 1100px。それ未満は初回、横スクロール可。スマホ用の組み替えは Won't

### 2.4 動き

- ホバー 150ms。トグル切替 200ms。`cubic-bezier(0.2, 0, 0, 1)`
- 切替で列の文字がクロスフェード。行の順番は動かない
- 検出枠は出現時に opacity のみ。枠を伸ばすアニメは初回やらない
- `prefers-reduced-motion` では即時切替

ボタンは44px以上。押した行は消さない。状態の文字が変わる。次の候補が入れ替わることを、行の順の変化だけで示す。説明の吹き出しは足さない。

### 4.6 書類

左右に2枚。同じ施設セレクタ。初期は翠嶺市総合体育館。

左: 避難所開設の記録（下書き）。右: 施設点検記録簿（抜粋）。欄は 04 の10。空欄は「—」。外壁を「異常なし」にしない。

下に対応の3行。点検の行から報告書の条件へ線または表。実装が簡単なら表でよい。線を引くなら SVG の長さは JS で測る。CSS 変数の dash アニメは使わない。

印刷ボタンは見た目だけでよい。初回、PDF生成は Won't として無効（押せない、理由はタイトル属性で「このデモでは出しません」）。

### 4.7 システム連携

04 の11。上に `5 / 8`。接続済み、確認中、未確認の数。進捗バーは 5/8。100% の印はゴールとして薄く置くが、バーは届かせない。

「あと3系統」の1行は出してよい。販売の文章にしない。

各行: 系統名、状態ピル、一言、右にドット。未確認の外壁だけ `--unknown`。

### 4.8 AIアシスタント

左はシェルのまま。本文は会話。

初期メッセージの次に、チップを3つ。Q1、Q2、Q3 の短い文（04 の9）。

- 今、開設できる避難所はどこですか
- 総合体育館は使えますか
- 確認できていない施設はなぜ残していますか

Q1 を初期表示で出しきってよい。返信の本文は 04 の文をそのまま。要約し直して数を変えない。

返信の下に、インシデントへの文字リンク。推奨アクションをチャットに再掲しない。重複すると数がずれやすい。

入力欄は出す。未知の文は 04 の1行だけ。

## 5. トグル仕様

- コントロールは2セグメント。「平常」「災害時」。平常が初期
- 並び、施設ID、施設名、行の高さは不変
- 変わるのは、期限グループの列が判定の列になること、理由列が出ること、行の左の印の色
- 200ms で文字が入れ替わる。行がスライドして並び替えるアニメは禁止（見せ場が消える）
- トグルしても INC-20260912-007 は残る。バッジの 1 は消えない
- URL に `view=daily` / `view=shelter` を付けてよい。戻ったとき状態を保つ
- 市庁舎は災害時も残す。判定「使える」、補足「指定避難所ではない」
- 確認できていない行は、災害時も色を塗らない。左の印は破線。文字は必須

## 6. 検出枠

画像に枠を焼かない。B の3枚と、画像確認の未入力写真に、実装で重ねる。

| 項目 | 指定 |
|---|---|
| 線 | 2px、`--ai`。角は 4px |
| 塗り | なし。内側を暗くしない |
| ラベル | 枠の上、左寄せ。白地に 12px。`車両 白バン` のように短い |
| 禁止語 | 危険、不審、侵入、監視、顔認識、氏名 |
| 確からしさ | 写真の上に出さない。相関パネルの 81% だけ |
| 人数 | `人物 8名`。個人の枠を8つ付けない。まとめて1枠 |
| 車両 | バンの外側に1枠。ナンバー位置を拡大しない |
| 欠落画像 | 枠だけ出さない。無地面にキャプションだけ |

「確認してください」はラベルにしない。画像確認の未入力行の状態文に置く。

## 7. コピー

- コンソール内は、画面で起きていることをそのまま書く
- キャプションは太字1行（状態）＋補足1行（意味）
- 使ってよい動詞: 見る、残す、どかす、確認する、ファイルする
- 使わない: DX、最適化、シームレス、レベニュー、OS、フル稼働、リアルタイム解析
- 「防災に建て付けた」は画面に出さない。資料の外の言葉
- 全体ステータスの言葉は「注意」。理由をホバーまたは近傍に1行: 条件付きと、確認できていない施設が残っている

Hero の本採用と代替は 4.1。コンソールの画面タイトルは次で固定する。

| 画面 | タイトル | サブ（1行まで） |
|---|---|---|
| ダッシュボード | 統合ダッシュボード | 開設できる場所と、記録がない場所 |
| 施設一覧 | 施設一覧 | 平常は期限。災害時は開設の判定 |
| インシデント | インシデント | 抽出した静止画と、平常時の点検 |
| 画像確認 | 画像確認 | 候補を挙げ、職員が押す |
| 書類 | 書類 | 同じ記録から、開設の下書きと点検簿 |
| 連携 | システム連携 | つながっているものと、紙のままのもの |
| AI | AIアシスタント | 開設できる場所を、記録の数で返す |

## 8. 地図

市内の模式。北、中央、東、西、南、緑・川辺。ピンは施設1件につき1。密集してよい。

ピンの中身は文字つきの点。凡例:

- 使える
- 条件付きで使える
- 使えない
- 確認できていない（破線）

総合体育館を押すとインシデント。他は施設一覧のその行へ。地図上にヒートや円の広がりを描かない。被害範囲を塗らない。

## 9. アクセシビリティと誠実さ

- 判定は色＋文字。アイコンだけにしない
- コントラスト: 本文は `--ink` on `--surface`。muted は注釈だけ。判定文字は白抜きにしない（薄い色の上の白は避ける）。ピルは薄地＋濃い文字
- フォーカスリングを消さない
- トグルとボタンの名前が無いアイコンにしない
- デモであることがシェル下部と書類の注記で常に分かる
- 問題を消さない。使える 12 のカードを、全面緑の成功画面にしない
- 記載のない点検を、プレースホルダの「正常」で埋めない
- モーション軽減時も、切替後の判定文字が読めること

## 10. 禁止（見た目）

- 断面のタワー、階の利用バー
- 在館人数、駐車場使用率、入退館件数
- 不審行動、警戒アラート、顔の枠、読めるナンバーの拡大
- 検知率、的中率、スコアのゲージを写真の上に置く
- 被災イラスト、土嚢、崩落、けが人
- 抽象図の自動再生
- 紫をボタン以外の装飾に散らす
- 英語の製品名、CONSOLE の小さいラベルの多用。Eyebrow は LP の和文でよい。英語が要るなら `DEMO` だけ
