# 防災施設コンソール — テーマ別要件定義書

初回実装用の正本。思想の元は [../02_防災施設管理デモ.md](../02_防災施設管理デモ.md)。画面に載せる固有名詞・件数・時刻・判定の内訳は [04_ペルソナと仮ナレッジ.md](04_ペルソナと仮ナレッジ.md) だけを正とする。本書ではその数を繰り返さない。

デモの仮称は「防災施設コンソール」。英語の OS 名は前面に出さない。

---

## 1. このデモで見せること

自治体は多くの公共施設を持っている。設備の不具合は普段から少しずつ出ている。記録は紙で、施設ごとにばらばらの場所にある。災害の日、その施設が避難所になる。使えるかどうかを、その場で判断することになる。

見せたいのは、平常時の点検記録と、災害時に必要な情報が同じものだということである。普段の点検が、そのまま「この施設は避難所として使えるか」の答えになる。

「防災」は予算と稟議を通すための入口である。中身は施設管理である。デモの中でその二重性を説明しない。同じ施設一覧の表示を切り替えて見せる。

もうひとつ、知見継承デモと同じ流れを入れる。

1. 施設の固定カメラから抽出した静止画に対して、AIが気になる箇所を挙げる
2. 職員が「対応が必要」「問題なし」を入力する
3. その入力が、次に挙がる箇所と、災害時の判定理由に残る

インシデント相関は、その記録が写真つきで一本につながる見せ場である。ライブ映像の解析ではない。

## 3. 背景

自治体系と関わるときに、「防災に建て付けた施設管理」があると横展開しやすい、という依頼がある。欲しいのは防災の専用システムに見える入口と、中身が施設管理であることの両方である。

URLを送って残る形にする。会議で投影して、切替と写真で話せる形にする。

Building OS Console（https://obs-demo.vercel.app/）は、LPと製品シェルの参考である。タワーの断面、在館、駐車場、不審行動の相関は借りない。

---

## 4. 課題

- 点検記録が施設ごとに紙で残り、災害の日に開かない
- 指定避難所の「使えるか」が、その場の記憶と電話になる
- 固定カメラがあっても、平常の点検と災害時の判断が別の仕事に見える
- 兼務の職員が、危機管理センター向けの画面を毎日開く前提にはできない

---

## 5. 対象ユーザー

詳細は [04_ペルソナと仮ナレッジ.md](04_ペルソナと仮ナレッジ.md)。

- 閲覧者: 財政・防災の稟議を通す人、防災担当、施設所管
- 操作の前提: 総務課で施設管理を1人で兼務している職員
- このデモが呼ばない相手: 大規模都市の危機管理センターの常駐オペレーター

理想感情: 「災害の日に、この総合体育館は使えるかが、普段の記録から分かる。」

## 6. 題材

架空の市を使う。実在の自治体名と施設名は使わない。

人口、施設の内訳、担当者名、サンプルインシデントの時刻と理由は 04 に置く。ここでは次だけ固定する。

- 人口4万2千人規模の市
- 対象は総合体育館、公民館、福祉センター、市庁舎、小中学校の体育館。合計22施設。主役は市の総合体育館。学校体育館は指定避難所として一覧に残し、カメラの中心にはしない
- サンプルインシデントは1本。指定避難所「翠嶺市総合体育館」。台風接近下
- 相関の結論は「条件付き」。動線が塞がれていることと、夜間の電源が確認できないこと。使えない・条件付きの理由は、平常時の点検記録から出す
- 判定は4つ。使える / 条件付きで使える / 使えない / 確認できていない。確認できていない施設を必ず残す
- 固定カメラは総合体育館のみ。公民館と学校のカメラは未接続として残す

---

## 7. 業務シナリオ

1. 平常時、期限が近い施設が点検の一覧に並ぶ
2. 固定カメラの静止画から、気になる箇所が挙がる。職員が対応の要否を押す
3. 台風接近の日、同じ一覧の表示を災害時に切り替える。並びと施設名は変わらない
4. 翠嶺市総合体育館のインシデントを開く。抽出静止画、検出ラベル、平常時の点検が一本になる
5. 同じ記録から、避難所開設の報告書と平常時の点検記録簿が出る

## 8. 情報アーキテクチャ

```text
LP
 └ コンソールを開く → 統合ダッシュボード
      ├ 施設一覧（平常 ⇄ 災害）
      ├ インシデント相関
      ├ 画像確認
      ├ 書類
      ├ システム連携
      └ AIアシスタント
```

ナビの並びは次のとおり。初期表示のコンソールは統合ダッシュボード。

1. 統合ダッシュボード
2. 施設一覧
3. インシデント
4. 画像確認
5. 書類
6. システム連携
7. AIアシスタント

AIへの入口はヘッダーの「AIに質問」でも開く。

### 8.1 各画面の目的と必須要素

**LP**
- 何のデモかを短く言う。写真が主役
- CTAは「コンソールを開く」と「AIに質問する」
- 機能カード4つ: 俯瞰 / 切替 / 相関 / 点検が次に効く
- 抽象図は置かない

**統合ダッシュボード**
- 全体ステータス、開設判定の内訳、進行中インシデント1本、市内の避難所ピン
- タワーの断面フロアマップは置かない

**施設一覧（見せ場）**
- 平常時は点検期限。災害時は開設判定
- 並びと施設名は不変。変わるのは列と色
- 「使えない」「条件付き」には平常時の点検が付く
- 記録がない施設は「確認できていない」。色を付けて埋めない

**インシデント相関（ビジュアルの見せ場）**
- 左: 時刻つきタイムラインと抽出静止画
- 中または右: 相関（動線、電源、備品、平常時記録）
- 右下: 推奨アクション。人が確認する前提
- 検出枠とラベルは実装で画像の上に重ねる。画像に焼き込まない

**画像確認**
- 気になる箇所の候補。ボタンは「対応が必要」「問題なし」
- 押した件数と内訳が出る。次の候補の出方が変わることを画面に残す
- AIは「危険」と書かない。「確認してください」

**書類**
- 避難所開設の報告書と、平常時の点検記録簿
- 同じレコードから2種類が出る対応が分かること

**システム連携**
- つながっているものと、紙のまま残っているもの
- 100%にしない。残りがあることが前提

**AIアシスタント**
- 最初の質問は「今、開設できる避難所はどこか」に固定した候補を出す
- 回答の数字は 04 と一致させる
- APIは呼ばない。固定の問答

## 9. Must / Should / Won't

### Must

- LPとコンソール。URL単体で紹介兼デモになる
- 施設一覧の平常 ⇄ 災害切替。並びと施設名は同じ
- サンプルインシデント1本を、抽出静止画と検出ラベルつきで見せる
- 画像確認で人が「対応が必要」「問題なし」を押せる
- 書類2種が同じ記録から出る
- 確認できていない施設を残す
- 画面の文言は「確認してください」。危険の断定をしない
- デモデータであることの表記
- 固有名詞と件数は 04 を参照する

### Should

- ダッシュボードに市内ピンの地図
- システム連携の進捗（接続済み / 確認中 / 未確認）
- AIの固定問答を2〜3本
- 切替時の短い遷移（200ms程度）
- 検出ラベルの確からしさ。ただし検知率・的中率とは書かない

### Won't（初回）

- 抽象図の自動進行と解決後の再演
- スマホ最適化、単一HTML、横幅370px
- AI API、体験コード、Core接続
- 被災の映像、けが人、崩れた建物
- 検知率、的中率、費用、補助金、導入の流れ
- 顔が判別できる写真、読めるナンバー、氏名、不審者ラベル
- 防犯、監視、という画面の言葉
- ライブ映像の解析演出
- 断面タワーマップ、在館人数、駐車場稼働率
- ROIシミュレータ導線

## 10. 誠実さの歯止め

- リアルタイムで映像を解析する演出をしない。出すのは、固定カメラから抽出した静止画と、その上に重ねる検出枠まで
- 車両と人物は、検出枠と短いラベルで示す（例: 車両 白バン / 東側搬入口、人物 8名 / 体育館入口）。特定の個人にしない
- AIに「危険」と断定させない。「確認してください」として人に渡す
- 判定できない施設を必ず残す。全施設に色が付く絵にしない
- 防犯や監視という言葉を使わない。見落としを減らし、開設の可否を記録から出す、という言い方にする
- 職員が記録を怠っている、という描き方をしない。1人で兼務していることを前提に置く
- 災害の被害そのものを描かない。建物、車両、人の位置、点検の期限で表す
- 記載のない施設の点検結果を、画面が自動で埋めない
- 問題をゼロにしない。条件付きと未確認が残る

## 11. 横展開

施設の種類と点検項目、災害時の見え方の言葉は設定データに持つ。本体の画面構造には書かない。初回のデータは 04 の翠嶺市。差し替え先の対応は次のとおり。実装の設定ファイル化は次フェーズ。本書では「ベタ書きしない」ことだけを決める。

| 相手 | 施設 | 災害時の見え方 |
|---|---|---|
| 自治体 | 総合体育館、公民館、庁舎（学校体育館は一覧に残す） | 避難所として使えるか |
| 商業施設の運営会社 | テナント区画、共用部 | 帰宅困難者を受け入れられるか |
| 病院、福祉法人 | 病棟、居室、設備 | 入院患者をどこに移すか |

知見継承デモとは、記録が溜まる → AIが候補を出す → 人が結果を入力する → 次の候補に加わる、を同じ流れとして説明する。画面の言葉だけが違う。

本デモは全庁を**読む**。防災が入口。1棟版が無くても稟議が終わる。記録が欠けている館は残す。

同じ市の1棟版 [../../disaster_prevention_demo02/docs/01_テーマ別要件定義書.md](../../disaster_prevention_demo02/docs/01_テーマ別要件定義書.md) は**書く**面。単体で1館提案が終わる。並べたとき、F01 の条件付きは体育館版の同じ K-G3 が根拠になる。実行時の連携はしない。画面に「1棟版が下にある」は出さない。優先順位と公共施設等総合管理計画は画面の題名にしない。役割の正本は [../../disaster_prevention_demo02/docs/施設カルテ_要件.md](../../disaster_prevention_demo02/docs/施設カルテ_要件.md)。

## 12. 成功条件

- URLを開いたとき、紹介ページと、触れるコンソールの両方がある
- 切替だけで、平常の点検と災害時の開設判定が同じ一覧だと分かる
- インシデント画面が、写真と検出枠で本格的なツールに見える
- 翠嶺市総合体育館の「条件付き」を、平常時の発電機記録と、搬入口の静止画の両方から説明できる
- 記録がない施設が、色の付かないまま残っている
- 危機管理センターの常駐画面には見えない。兼務1人が投影して話せる密度である
